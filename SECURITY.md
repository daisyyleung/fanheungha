# Security policy

## Reporting a vulnerability

Please do not open a public issue or discussion with exploit details, credentials,
or personal data. If GitHub private vulnerability reporting is enabled for this
repository, use **Security → Report a vulnerability** so the report stays private.
If that option is unavailable, open only a minimal public issue asking the
maintainers to provide a private reporting route. Do not include exploit or
reproduction details, credentials, secrets, or personal data in that issue.

Reports should describe the affected version or public tag, impact, reproduction
steps that do not include real user data, and a safe way to contact you. Allow time
for triage and a coordinated fix before public disclosure.

## Scope

This policy covers the application code, Worker routes, D1 access, release
workflows, and packaged dependencies in this repository. Do not send secrets,
production identifiers, database exports, or private travel records in a report.
